Tools Reference

The tools documented for the ThriveStack MCP Server, with parameters and what each one does.

This page documents 39 tools of the ThriveStack MCP Server, and its one prompt. They cover your brands and brand kit, AI-search visibility and citations, the AI answers and sources behind each tracked prompt, the sources AI answers draw on, your site’s crawl and indexing health, page traffic and Google search performance, the content audit, prompt research, and content recommendations.

38 of the 39 tools are read-only. The only tool that changes anything is save_content_recommendations, which saves recommendations to your brand as suggested items for your team. It cannot approve, dismiss, assign or delete anything, and your AI client asks you to confirm before it runs.

None of these tools take a project_id or similar tenant parameter. Your product and environment are resolved automatically from how you authenticated (OAuth session or Personal Access Token) — see Setup.

Your AI assistant calls these automatically based on your questions. The server also provides one prompt, ai_visibility_analyst, a ready-made content-strategy analysis — see Prompts. It does not expose any MCP resources.

Response format

There is no single universal response envelope — each tool returns the JSON shape natural to its own data. The visibility and recommendation tools return structured report objects, and check_connection returns a small fixed object.

Tools whose description says they return a “clear empty” or “no-data” result are designed to return an empty-but-valid result rather than an error when there’s nothing yet (for example, a domain that hasn’t been probed). Treat that as “nothing here yet”, not a failure. Large results are paged or capped; the tools that page accept page and page_size (or limit and offset).

Brands & Account

get_accessible_brands

Lists the brands (products) the signed-in ThriveStack account can access, with name and domain for each. These are the brands the account can switch between, and the domains the other tools accept. The result is the same whether you connect with OAuth or a personal access token.

No input parameters required.

get_brand_information

Returns the saved brand profile for a domain, as captured during AI Visibility setup and any later edits: description, value offering, industry, HQ country, business model, products and services, brand identity, customer segments, target markets, tracked competitors, tracked topics, language, monitored AI engines, buyer-intent mix, and setup progress (last_completed_step, user_edited).

ParameterTypeRequiredDescription
domainstringYesDomain to fetch the brand profile for, e.g. acme.com

get_brand_kit

The brand kit saved for a domain, which guides how generated content should sound: voice (tone sliders such as formal to casual, author persona, sounds-like and not-like examples), rules (dos and don’ts) and naming (official brand name and aliases), plus version and updated_at.

Good to know

  • If no kit has been saved yet, the tool returns saved=false with an empty kit. That is not an error; it means the brand kit has not been set up for the domain.
  • The brand kit holds voice, rules and naming only. It does not include logos, colours or fonts.
ParameterTypeRequiredDescription
domainstringYesDomain to fetch the brand kit for, e.g. acme.com

Sources & Pages

get_url_report

Per-URL retrieval and citation metrics for every source URL AI answers drew on for a domain’s tracked questions: which specific pages are retrieved and cited, and how often, with each URL’s type, domain type and source class (owned, earned or other cited). It lists source URLs from any site that AI answers cited, not only the brand’s own pages.

Good to know

  • Without a date window it covers the most recent completed probe run. Source metrics are computed after a run finishes; until then the tool returns has_run=true, urls_computed=false rather than an empty list. With start_date/end_date it covers every run in the window.
  • retrievals is how many answers cited the URL, and retrieved_pct is the percent of all answers that cited it.
  • citation_rate is the average number of times the URL was cited per answer that cited it. It is 1.0 or more and is not a percentage.
  • Default sort is retrievals, highest first.

Site & Crawl Health

list_urls

Paged table of the brand's URLs (brand from your token), one row per URL that the brand's Search Console sync knows about: sitemap URLs plus any pages added by hand. Each row combines four sources: Google indexing (indexState, coverageDetail, crawlAllowed, lastCrawlTime), AI-crawler reach (crawlHits and crawlBots), the content audit (contentStatus, seoScore, entityScore, only for audited pages) and AI citations (cited, citedPromptCount, and citedBy, up to 10 of the citing prompts, newest first, each with probed_at). Filters are ANDed; a comma list inside one filter means any of.

Good to know

  • crawlHits and crawlBots count requests made by AI crawlers such as GPTBot and ClaudeBot. They are not human visits. Human visits come from get_page_traffic.
  • The list is empty until Search Console is connected and has synced. get_search_console_status shows the connection.
  • The response includes columns, which says which sources are set up (indexed, crawled, content). When one is false, its fields are absent because the source is not set up. That is different from a value of zero.
  • total counts every matching row. Page through them with page and page_size.
  • Pages that AI answers cite on any site, not only the brand's own, are covered by get_url_report.

This tool takes no domain parameter. It always reads the brand your token belongs to.

Traffic & Search Performance

These tools show how much real traffic each page gets and how it performs in Google, next to the AI-crawler and citation data above. Together with list_urls they give a page-by-page view of a site, which is what a content calendar needs.

Matching pages across tools. get_page_traffic and get_search_performance identify a page by its normalised path: host, query string and trailing slash removed, lower-case. A page therefore has the same key in both, and you can join them on it.

No data is not zero. Each tool says in meta whether its source is connected. If it is not, the tool has no data to report, which is different from a page with zero visits or zero clicks.

get_page_traffic

Human visits per page from the connected Google Analytics, across every channel, not only AI-referred ones. For each landing page it returns:

  • sessions in the window, split into organic search, direct, AI referral and other (paid and email visits are included in these);
  • key events (conversions);
  • the last day with sessions in the window;
  • first_seen, the oldest day Google Analytics shows sessions for the page. This is a lower bound on when the page went live, because history starts when the connection first synced.

A session counts on the page it started on, so this is not a page-view count. Defaults to the last 28 days. Results are sorted and paged on the server, with totals over the whole filtered set.

Good to know

  • Totals can sit a few percent below the traffic attribution overview. That report reads Google Analytics by channel and day, while this one reads it by landing page, so the two do not match exactly.
  • meta says whether Google Analytics is connected (configured=false means there is no data to report, not zero visits), whether it is still syncing, and how many sessions had no landing page or were grouped into Google's “(other)” row. When that happens, the page list is incomplete.
  • Crawler hits from Cloudflare, Vercel or WordPress are AI-bot requests and are not part of these visits.

domainstringYesBrand domain, e.g. acme.com
end_datestringNoEnd of the window, YYYY-MM-DD, inclusive
pagenumberNoPage number, 1-indexed (default 1)
page_sizenumberNoRows per page (default 25, max 200)
property_idstringNoOnly this Google Analytics property, as listed in properties of a previous response. Omit to sum all connected properties.
searchstringNoOnly pages whose path contains this text, case-insensitive
sort_bystringNoSort column (default sessions). One of: sessions, organic_sessions, direct_sessions, ai_sessions, other_sessions, key_events, last_seen, page.
sort_dirstringNoSort direction (default desc, or asc when sorting by page). One of: asc, desc.
start_datestringNoStart of the window, YYYY-MM-DD. Give it with end_date; omit both for the last 28 days.

get_search_performance

Google Search Console clicks and impressions per page for the brand on your token. For each page it returns clicks, impressions, CTR (a decimal, so 0.0123 means 1.23%) and average position (1 is the top of the results, weighted by impressions), summed over the window, plus totals over the whole filtered set. example_url shows one full URL for the page.

Defaults to the last 28 days ending two days ago, because Search Console runs about two days behind. Results are sorted and paged on the server.

Good to know

  • The data comes from a daily sync. meta says whether Search Console is connected (configured=false means there is no data, not zero clicks), whether the first sync is still running (syncing), the oldest and newest day held (data_from, data_through), and warns when your window reaches outside them.
  • Only pages that Google showed in its results have a row. A page with no row was not shown in the window.
  • get_search_console_status shows the connection and sync state.

This tool takes no domain parameter. It always reads the brand your token belongs to.

get_attribution_health

A plain-language health check of the data behind the attribution dashboards, in one call. Read-only.

  • Sources. For Google Analytics, Cloudflare, Vercel, WordPress and revenue, it reports whether the source is connected, still syncing, working or needs attention, with when it last synced and a short reason.
  • AI crawler tracking. It reports whether the add-on is on, how much of it is used, and whether a crawler visit has been confirmed.
  • Overall. overall is one of working, setting_up, needs_attention, not_connected or unknown (when the sources could not be read). attention lists what needs a look, as plain sentences.
  • Coverage. coverage says what each source can tell you. Google Analytics is the only source of human visits. Cloudflare, Vercel and WordPress report AI bot requests only, so a connected crawler source never means visit data. Coverage is explanation only; it does not change attention or overall.

If one part cannot be read, its entry carries an error message and the others still report.

ParameterTypeRequiredDescription
domainstringYesBrand domain, e.g. acme.com

Content Audit

These tools show which pages are tracked for the content audit, how many page audits your plan allows and how many are used, and which sitemap pages you could add.

get_content_audit_summary

Content audit status for a brand’s domain: how many pages are audited, queued and active, the plan’s page-audit limit (page_audits_purchased), how many are used (page_audits_consumed) and pages_remaining (limit minus used). Each page row has its SEO and AEO scores, pending actions by priority, last audit time and whether AI answers cite it. It also returns sitemap_status and coverage_warnings when present.

Good to know

  • pages_remaining is absent when the plan figures are unavailable.
  • Page rows come in pages: total, returned and next_page say where you are.
  • Set include_sitemap to also list sitemap and AI-cited pages that are not in the report (in_report=false). Those pages are not counted in any total.

list_prompt_research

Lists a brand's prompt research sessions: each is a run that discovers the questions buyers ask AI about the brand's category, from which the user picks prompts to track.

get_prompt_research

Returns one prompt research session's researched prompts and personas. Each prompt has prompt_text, topic, persona, branding (branded or non-branded), intent (informational, commercial or transactional), country, language, recommended and tracked. Prompts are grouped either by topic or by persona. Get the id from list_prompt_research.

ParameterTypeRequiredDescription

page_sizenumberNoPrompts per page (default 100, max 200)
tracked_onlybooleanNoIf true, return only prompts already tracked

Drafting & Saving

generate_content_outline

Generates a content outline (structure only, not finished copy) for one owned-media content recommendation: headings, an answer-first opening summary, FAQ questions, and suggested schema markup types. The outline is generated on request and nothing is saved; calling it again produces a new one.

ParameterTypeRequiredDescription
content_typestringYesOwned-media content type — one of: Homepage, Domain, Product, Comparison, Article, Educational, Blog, Guide, How-to, Documentation, Listicle, Wiki
titlestringYesThe content recommendation's title to outline (e.g. from get_owned_content_recommendations)

save_content_recommendations

Saves content recommendations (owned and/or earned) to the brand's recommendations list as 'suggested' items for the team to act on. This is the only tool that writes data, and it is deliberately narrow: it creates new 'suggested' items or refreshes ones still 'suggested'.

ParameterTypeRequiredDescription
domainstringYesBrand domain the recommendations are for
recommendationsobject[]YesRecommendations to save (max 30)
probe_run_idstringNoThe probe run the evidence came from (run_id from get_citation_probe_data). Omit to use the latest run with results.
